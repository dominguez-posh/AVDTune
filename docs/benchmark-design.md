# Benchmark design (for the user's approval)

Status: DESIGN, no product code yet. Issue #13. Plan: `docs/plans/avdtune.md` sections 1c, 6, 6a, 6b, 7a. Facts checked on 2026-11-15; each one carries its source, and what could not be checked is marked **(nicht verifiziert)**. Open decisions for the user are in section 9.

Fixed by the user: three separate scores (Host = overall score, FSLogix, GPU); Host weights Applications 30, CPU 25, OS disk 20, Memory 10, Remote display 10, Network 5; no test user and no logon test; reference = a typical current AVD host (common 8-vCPU size, Premium SSD, Marketplace image Windows 11 multi-session + M365 without optimization; FSLogix reference: Premium share with private endpoint); baseline in the initial analysis, required before every "Abschliessen"; benchmark-only mode; optional capacity simulation (about 30 min) in the administrator's session; stand-alone script in the public repo `dominguez-posh/AVD-Benchmark`.

## 0. Parts

| Part | What | Where |
|---|---|---|
| `AVDTune.Bench.exe` | our own measure program, C#, .NET 10 self-contained single file, x64 (decision D4). Does every measurement except disk I/O; talks JSON on stdout. No third-party libraries: Windows APIs through own P/Invoke and COM interop (Media Foundation, Direct3D 11, DXGI, VirtDisk, UI Automation, `HttpClient`) | source `Bench/` in the AVDTune repo, built by the release workflow into the ZIP (`Bench/bin/AVDTune.Bench.exe`), size and SHA256 in the release manifest (`Files` and `Bench`), started only after the check below (plan 9a, issue #19) |
| `Modules/AVDTune.Benchmark.psm1` | orchestration in Windows PowerShell 5.1: preconditions, quiet mode, runs, scores, comparison, report. No UI, so the GUI, `Start-AVDTune.ps1 -Benchmark` and the stand-alone script use the same code | AVDTune repo |
| diskspd 2.3 | Microsoft's storage load tool, OS disk and share | downloaded at run time (section 6, decision D5) |
| Speedometer 3.1 | browser benchmark, local copy | `Bench/data/speedometer-3.1/` |
| `Bench/data/` | `references-<benchmarkVersion>.json`, synthetic test documents, test web pages, video clips generated by our own code | AVDTune repo |
| `Tests\Check-Benchmark.ps1` | diskspd XML parser, score math, comparison, schema, cleanup check, against fixtures | AVDTune repo |

Every measure has an ID (`host.cpu.single`), a unit, a direction (higher or lower is better), a duration and a status (`ok`, `skipped`, `unsupported`, `failed`, with the reason).

## 1. Measures per category

Durations are per run; a full benchmark is one warm-up run and three measured runs (section 3).

### 1.1 Host-Score

**CPU (25 %)**. `AVDTune.Bench.exe cpu`. Workload mix, all data generated from a fixed seed in memory before the timer starts: Deflate compress and decompress of a 32 MB text-like corpus (`System.IO.Compression`), JSON parse and serialize of a 10 MB document (`System.Text.Json`), regex search over 20 MB of log lines (`RegexOptions.Compiled`), sort of 2 million strings. One mix iteration = all four. The build is ReadyToRun with tiered PGO off and each workload has 1 s of in-process warm-up, so the JIT state is the same on every machine.

| ID | Measure | Unit, better | Duration |
|---|---|---|---|
| `host.cpu.single` | mix on 1 thread | iterations/s, higher | 3 s per workload |
| `host.cpu.multi` | same mix on N threads, N = logical processors, own data per thread | iterations/s total, higher | 3 s per workload |
| `host.cpu.sustained` | multi mix for 60 s; throughput of the last 10 s / first 10 s (throttling, noisy neighbour, CPU credit) | ratio, higher | 60 s, only in run 1 |
| `host.cpu.aes` | AES-256-GCM encrypt, 64 KB blocks, 1 thread (`AesGcm`, CNG, AES-NI) | GB/s, higher | 3 s |
| `host.cpu.sha` | SHA-256, 64 KB blocks, 1 thread | GB/s, higher | 3 s |

Shown, not indexed: scaling factor multi/single (it is derived from two measures already counted; deviation from plan 6a, decision D8).

**Memory (10 %)**. `AVDTune.Bench.exe mem`.

| ID | Measure | Unit, better | Duration |
|---|---|---|---|
| `host.mem.bandwidth` | `Buffer.MemoryCopy` of 256 MB buffers, threads = physical cores | GB/s, higher | 3 s |
| `host.mem.latency` | pointer chase through a 512 MB array, random cyclic permutation (Sattolo), 64-byte stride | ns per load, lower | 3 s |
| `host.mem.alloc` | .NET allocation churn, objects 64 B to 8 KB, workstation concurrent GC | MB/s, higher | 3 s |

**OS disk (20 %)**. diskspd on the system drive, test file `C:\ProgramData\AVDTune\benchmark\work\<runId>\disk.dat`, 4 GiB, created once per benchmark (`-c4G`), random buffer contents (`-Z1M`) so compression and deduplication do not flatter. `-Sh` (no software and no hardware write cache) makes it a device measure; the user's view with the Windows cache is in the small-file test and the application starts. Output `-Rxml`, parsed for IOPS, MB/s and latency percentiles.

| ID | Command line (diskspd 2.3) | Value, better |
|---|---|---|
| `host.disk.rr.qd1.p50`, `.p99` | `diskspd -b4K -r -o1 -t1 -w0 -d12 -W3 -C2 -Sh -L -Z1M -Rxml <file>` | read latency p50 and p99, ms, lower |
| `host.disk.rw.qd1.p50`, `.p99` | `diskspd -b4K -r -o1 -t1 -w100 -d12 -W3 -C2 -Sh -L -Z1M -Rxml <file>` | write latency p50 and p99, ms, lower |
| `host.disk.mix.qd32` | `diskspd -b4K -r -o8 -t4 -w30 -d12 -W3 -C2 -Sh -L -Z1M -Rxml <file>` (4 threads x 8 = 32 outstanding) | IOPS, higher |
| `host.disk.seq.read` | `diskspd -b1M -si -o8 -t1 -w0 -d12 -W3 -C2 -Sh -Rxml <file>` | MB/s, higher |
| `host.disk.seq.write` | `diskspd -b1M -si -o8 -t1 -w100 -d12 -W3 -C2 -Sh -Z1M -Rxml <file>` | MB/s, higher |
| `host.disk.smallfiles` | `AVDTune.Bench.exe files`: create 5000 files (4 to 64 KB, fixed seed) in 50 folders, read all, delete all, through the normal Windows cache (includes Defender and filter drivers) | files/s over the three phases, higher |

diskspd 2.3 changed two defaults (P-cores before E-cores, buffer separation, release notes) and asks for rebaselining; the diskspd version is therefore part of the benchmark version (section 2). Azure caches the OS disk on the host (default ReadWrite for OS disks, **nicht verifiziert** for every image); this is what the user gets and is stated in the report.

**Applications (30 %)**. `AVDTune.Bench.exe apps`. Each application is started by the program as a child in a job object (so only our own processes are closed), with a timeout of 60 s (then `failed`). "Ready" = the main window is visible, the named UI Automation element exists and `WaitForInputIdle` returned; the time runs from `CreateProcess` to ready.

| App | Start | Ready |
|---|---|---|
| Word | `WINWORD.EXE /q /n "<work>\bench.docx"` (20 pages, generated test document) | window class `OpusApp` with a document pane `_WwG` |
| Excel | `EXCEL.EXE /e "<work>\bench.xlsx"` (10 sheets, 50 000 formulas) | `XLMAIN` with a workbook window `EXCEL7`, calculation state done |
| Outlook (classic, offline) | `OUTLOOK.EXE /profile AVDTuneBench /nopreview`; the profile has only a PST with 2000 generated mails, created before the run, removed after | `rctrl_renwnd32` with the folder list |
| Edge | `msedge.exe --user-data-dir=<temp> --no-first-run --no-default-browser-check http://127.0.0.1:<port>/start.html` | the local page calls back to our loopback server after `load` and `requestIdleCallback` |
| Teams (new) | activation by AUMID (`IApplicationActivationManager`) | main window visible and input idle (the sign-in screen is enough) **(nicht verifiziert: window class)** |
| File Explorer | `explorer.exe /n,"<work>\folder500"` (500 files) | UIA items view with 500 items; only the new window is closed, explorer.exe is never killed |
| PowerShell | `powershell.exe -NoProfile -NonInteractive -Command exit`, 5 times | median wall time |

- Cold and warm: per app first a cold start (all its processes closed, then the standby list purged with `NtSetSystemInformation(SystemMemoryListInformation, MemoryPurgeStandbyList)`, so files come from disk as after a reboot; undocumented API, **nicht verifiziert** on Windows 11 25H2, decision D6), close, then a warm start. IDs `host.app.<app>.cold` and `.warm`, ms, lower. PowerShell only warm.
- First-run dialogs: Office's first-run and privacy dialogs and Edge's first run are suppressed for this run only by policy values in the administrator's HKCU (value names fixed in the build, **nicht verifiziert** which are needed on M365 current channel), written to the restore journal and removed after. Shared computer activation without a licence token shows a sign-in note; the window counts as ready anyway.
- Software that is not installed: its measures are `skipped` with the reason (benchmark-only on systems without Office). Classic Outlook only; new Outlook cannot open offline and is listed as information.
- Cleanup: WM_CLOSE, then terminate the job; test files, PST, MAPI profile, temporary Edge profile deleted; check in section 6.

| ID | Measure | Unit, better |
|---|---|---|
| `host.app.speedometer` | Speedometer 3.1, local copy of `WebKit/Speedometer` branch `release/3.1` (commit `1386415b`, 2025-03-11), licence BSD-2-Clause (Apple, Google, Mozilla, Microsoft; the LICENSE file is kept next to the copy). Served by the measure program from `127.0.0.1:<random port>` (only that folder, path traversal refused); Edge with a temporary profile, window 1280x900, URL `index.html?startAutomatically&iterationCount=2` (quick: 1). Result read through the DevTools protocol on a random loopback port (`--remote-debugging-port`): `document.getElementById('result-number').textContent` once `location.hash` is `#summary`. **Remote display (10 %)**. Synthetic clips generated by our code from a fixed seed (no media licences): "desktop" (text windows, scrolling, a moving window and cursor) and "video" (full motion), 1920x1080 NV12, 300 frames each.

| ID | Measure | Unit, better |
|---|---|---|

Shown as information: storage kind, tier, provisioned size and IOPS/throughput limits (ARM, full tool only), private endpoint yes/no, SMB channel encryption, protocol dialect of the session (`Get-SmbConnection`).

### 1.3 GPU-Score

Only when DXGI lists a hardware adapter other than the Microsoft Basic Render Driver (vendor 0x1414); otherwise "nicht vorhanden". The adapter is chosen by LUID. Shaders are HLSL compiled at run time with `d3dcompiler_47.dll` from System32.

| Category (weight) | ID | Measure | Unit, better |
|---|---|---|---|
| 3D rendering (35 %) | `gpu.d3d11.1080`, `gpu.d3d11.2160` | fixed Direct3D 11 scene (about 2 million triangles instanced, per-pixel lighting, 4 procedural textures, no MSAA) into an off-screen texture at 1920x1080 and 3840x2160, 10 s each, frames counted with GPU timestamp queries | frames/s, higher |
| Video encode (30 %) | `gpu.enc.h264`, `gpu.enc.hevc`, `gpu.enc.av1` | hardware encoder found with `MFTEnumEx(MFT_CATEGORY_VIDEO_ENCODER, MFT_ENUM_FLAG_HARDWARE \| MFT_ENUM_FLAG_SORTANDFILTER)` per output type, async MFT fed with NV12 textures through `IMFDXGIDeviceManager`, desktop and video clip at 1920x1080, low latency, CBR 10 Mbit/s | frames/s, higher |
| Video decode (15 %) | `gpu.dec.h264`, `gpu.dec.hevc`, `gpu.dec.av1` | hardware decode (Source Reader with a D3D manager and hardware transforms) of fixed 3840x2160 clips, 10 s | frames/s, higher |
| Compute (20 %) | `gpu.cs.gflops`, `gpu.cs.bandwidth` | DirectCompute FMA kernel; copy kernel over a 1 GiB buffer | GFLOPS / GB/s, higher |

- A codec the GPU does not support is `unsupported` and named; the category is the mean of the rest (comparison rule in 2.3).
- The decode clips are encoded in the build pipeline from our own synthetic frames and shipped as data (MP4). Whether H.265 and AV1 in MP4 decode without the Store codec extensions is **nicht verifiziert**; Learn (graphics-enable-gpu-acceleration, 2025-05-28) says the Microsoft HEVC codec is in new installations of Windows 11 22H2 and later.
- DirectX 12: information only (feature level, WARP or hardware), not indexed, so a host without DX12 still gets a comparable score (deviation from plan 6a, decision D8).
- Shown as information: adapter, driver, VRAM, vGPU profile (`nvidia-smi` when present), and the RDS policies from Learn: "Use hardware graphics adapters for all Remote Desktop Services sessions", "Prioritize H.264/AVC 444 Graphics mode", "Configure H.264/AVC hardware encoding", H.265 hardware encoding. A GPU host without the first policy gets the red hint of plan 6a.
- **(nicht verifiziert)** whether the hardware adapter can be used inside the administrator's RDP session when the policy is off; to be tried on an NV VM before the build.

## 2. Reference values and calculation

### 2.1 Reference measurement (once per benchmark version)

1. Benchmark version `B<major>.<minor>`. Major changes with any change that alters a value: a measure, a parameter, a test file, diskspd version, Speedometer commit, .NET version of the measure program, clip, reference VM. Minor only for report or text changes.
2. Reference host (decision D1): three fresh VMs of the chosen size in the same region, each from the plain Marketplace image Windows 11 multi-session + M365 of that month, no optimization, Premium SSD OS disk, rebooted, 10 minutes idle. On each VM two full benchmarks on different days. Reference value per measure = median of the six results. CPU model of each VM recorded (Azure gives different CPUs for one size); a VM whose CPU differs from the others is replaced.
3. FSLogix reference (D2): a Premium file share with private endpoint in the same region, measured from a reference host. GPU reference (D3): a common GPU size, same procedure.
4. Frozen in `Bench/data/references-B1.0.json`: value per measure, unit, direction, VM size, CPU model, region, image version, date, tool hashes. Every result names the reference it was scored against. Results of different major versions are never compared as scores; the report then shows the raw values side by side with a note.

### 2.2 Index and scores

- Index per measure: higher is better: `I = 1000 x value / reference`; lower is better: `I = 1000 x reference / value`. The reference host scores 1000 everywhere.
- Category = geometric mean of its measures' indexes (equal weight inside a category).
- Score = weighted geometric mean of the categories: `S = exp( sum(w_c x ln I_c) / sum(w_c) )`, summed over the categories that ran.

Example (OS disk category): read latency p50 0.080 ms against 0.105 ms gives 1313; 70/30 IOPS 18 500 against 12 000 gives 1542; sequential read 250 against 200 MB/s gives 1250; small files 2400 against 1900 files/s gives 1263. Category = (1313 x 1542 x 1250 x 1263)^(1/4) = 1337.
Example (Host-Score): CPU 1180, Memory 960, OS disk 1420, Applications 1050, Remote display 1000, Network 880 with weights 25/10/20/30/10/5 gives `exp(0.25 ln 1180 + 0.10 ln 960 + 0.20 ln 1420 + 0.30 ln 1050 + 0.10 ln 1000 + 0.05 ln 880)` = **1123** (the arithmetic mean would be 1134: the geometric mean dampens the strong disk).

### 2.3 Comparison

- Delta per category and score in percent; green above +10 %, red below -10 % (plan 6).
- Scores are compared only when the benchmark major version is the same and the same measures ran. When a measure is missing on one side (no Office, a codec), the score is recomputed for both on the common set and marked "gemeinsame Messungen"; when a whole category is missing, the categories are shown side by side without a score delta (plan 6b).
- Quick results are never compared with full ones and do not count for "Abschliessen".

## 3. Repeatability

- **Preconditions** (checked, the run does not start otherwise): elevated; no other user session, active or disconnected (`WTSEnumerateSessions`), the blocking ones named; AVDTune does nothing else (mutex); uptime at least 5 minutes; total CPU below 10 % for 60 s; at least 10 GiB free on C:; no pending reboot (warning, a reboot before the benchmark is recommended); on battery or power saver: warning. In the full tool also no maintenance run active.
- **Quiet mode** for the run, every change first written to `C:\ProgramData\AVDTune\benchmark\restore.json`:
  - Windows Update: `wuauserv` and `UsoSvc` stopped if running (start type unchanged), started again after. `WaaSMedicSvc` is protected and not touched. If an installation is in progress (WUA `IUpdateInstaller.IsBusy`), the benchmark waits up to 10 min, then refuses.
  - Indexer: `WSearch` stopped if running, start type unchanged, started again after.
  - Defender: no setting is changed (tamper protection, and Defender is part of what users get). Before the start the scheduled scan time is read (`Get-MpPreference`) and the run refuses when a scan is due in the next 30 minutes; a running scan shows up in the disturber watch.
  - Disturber watch: CPU of `MsMpEng`, `TiWorker`, `TrustedInstaller`, `SearchIndexer`, `MoUsoCoreWorker`, `CompatTelRunner`, `OfficeClickToRun`, `msiexec` and of all processes not ours, sampled every second. Above 10 % of one core on average during a measure: that measure is repeated once; still disturbed, it is marked with the process name.
  - Safe restore: at the end, on error, on Ctrl+C and in a `finally` block. If the process dies, a one-shot scheduled task `AVDTune-BenchmarkRestore` (SYSTEM, at start-up, created at the beginning, removed at the end) restores from the journal at the next boot and deletes itself; AVDTune also restores at its next start when the journal exists.
- **Runs**: one warm-up run (shortened: no Speedometer, diskspd 5 s; discarded), then 3 runs in the same order; `host.cpu.sustained` once. Value = median of the 3 runs. Coefficient of variation CV = standard deviation / mean; CV above 10 % = "instabil" (example: 1180, 1175, 1210 gives CV 1.6 %). An unstable measure is repeated once automatically; still unstable, it counts but is flagged (decision D7).
- **Recorded with each result** (plan 6a): benchmark version, reference, VM size, region, CPU model, vCPU, RAM, disk type, size and controller, Windows edition and build/UBR, Office build and channel, FSLogix version, image version, time, mode, tool hashes, disturbers.
- **Run time** (estimates, measured on the reference and then stated in the UI):

| Part | Full | Quick |
|---|---|---|
| Host-Score | about 17 min (warm-up 1.5, 3 runs of about 4.75, sustained 1, preparation 0.5) | about 3 min: 1 run, diskspd 5 s, Speedometer 1 iteration, no sustained, no cold starts |
| FSLogix-Score | + about 8 min | + about 2 min |
| GPU-Score | + about 6 min | + about 1.5 min |
| Capacity simulation | optional, about 30 min | not available |

## 4. Capacity simulation ("Kapazitaet", optional)

- **Probe** (one interactive user, in the administrator's session): a fixed script with UI Automation, about 60 s per cycle, 12 actions: open the test document in Word, type a paragraph, apply a style, save; open the test workbook in Excel, change an input cell, wait for recalculation, insert a chart; Outlook: open a mail, search, reply into a draft; Edge: open a local test page, scroll, start a local video; open a 50-page PDF in Edge, scroll and zoom; copy 200 files in Explorer and zip them; idle pauses of 2 to 5 s. Each action is timed from the input to its ready condition (UIA property or element change, `WaitForInputIdle`). Input goes through UIA patterns (Value, Text, Invoke) only to windows of processes we started, never as global keystrokes; a global hotkey (Ctrl+Alt+End) and any foreground change to another process stop the simulation.
- **Calibration**: during 3 probe cycles at level 1 the program records the probe's footprint per minute: CPU seconds, working set, disk operations and bytes.
- **Load workers**: `AVDTune.Bench.exe load --user <n>`, one process per simulated user, normal priority, each in a job object, each with its own folder. A worker replays the calibrated footprint: the CPU workloads of 1.1 for the measured CPU seconds, a working set of the measured size allocated and touched, the same small-file I/O, and on VMs without GPU a software H.264 encode of the desktop clip at 1920x1080 and 10 frames/s (the RDP cost of a session, decision D10).
- **Levels**: probe alone, then 1, 2, 4, 6, 8, then +4 per level; each level 60 s ramp and 120 s of measuring (at least 2 probe cycles). Stop when the threshold is passed by two levels, memory commit is above 90 %, the level is 4 x vCPU, or 30 minutes are reached.
- **Threshold**: median total response time of a probe cycle 50 % above the level-1 value. Capacity = users at the crossing, interpolated linearly between the two levels around it, as "geschaetzte Nutzer (eigene Methode, an VSImax angelehnt, kein Login VSI Ergebnis)".
- **Output**: table per level (users, median and p95 per action and total, CPU %, available memory, disk queue length), the curve, the estimate; compared with the last run of the same VM size. Stored like a benchmark, not part of the scores, not required for "Abschliessen".

## 6. Security

- Runs elevated only (AVDTune and the stand-alone script refuse otherwise). The measure program runs from the protected install folder of the release (`<install>\<version>\Bench\bin`, never from `Bench\out` or `tools\`). Before each start it is held open with `FileShare.Read` (no write, delete or rename), size and SHA256 of the held file are compared with the `Bench` entry of the saved release manifest, and only then the process starts; no entry or no match means no start and the engine precondition shows why (`Open-AVDTuneVerifiedBenchExe`). The stand-alone script does the same with the manifest of its own release.
- **Downloads**: diskspd from `https://github.com/microsoft/diskspd/releases/download/v2.3/DiskSpd.ZIP` (3 606 329 bytes, SHA256 `18609981e8b04b4f645f1fd182ad0541615fe71722de36a9a933c54f747218a3`, the digest GitHub shows for the asset; release 2026-09-04). After unzipping, `amd64\diskspd.exe` must have SHA256 `DD4E57E1E8CCAF5D6437938F8AAB7F17E9A1E6D8FBA8A093006B7CADF16FAEA2` and a valid Authenticode signature by Microsoft Corporation (checked 2026-11-15: valid, subject `CN=Microsoft Windows, O=Microsoft Corporation`, file version 2.3.0). Both values are pinned in the benchmark data, a mismatch stops the run. Offline: the administrator can place the ZIP by hand, same checks. The network test file is never written or executed.
- **Licences**: diskspd source is MIT (repo LICENSE), but the binary ZIP carries Microsoft Software License Terms ("EULA") that forbid to "publish the software for others to copy" and allow use "to design, develop and test your programs". So the binary is never put into our repos or ZIPs; it is downloaded by each user (decision D5). Speedometer: BSD-2-Clause, copy with its LICENSE. No Ookla or other third-party binaries. Note: `AVD-Benchmark` today holds `diskspd.exe` and `diskspd.pdb` in the public repo, which the binary terms do not allow (decision D11).
- **Share access** in benchmark-only mode: key or password read into a `SecureString`, used for one deviceless SMB connection to `\\host\share` (`WNetAddConnection2` without `CONNECT_UPDATE_PROFILE`, nothing in Credential Manager), the unmanaged copy zeroed right after the call, connection removed with `WNetCancelConnection2` at the end and on error. Never in settings, protocol, report, JSON, command lines or environment variables; diskspd and the measure program get only the UNC path. The field says that the account key gives full access to the storage account and that only a test folder is used and removed.
- **Loopback only**: the HTTP server for Speedometer and the test pages and the Edge DevTools port bind to 127.0.0.1 on random ports, live only during the test, the temporary Edge profile is deleted. Risk named: another local process could connect to the DevTools port during the test; acceptable because the profile is empty and other sessions are not allowed during the run.
- **No command lines from data**: diskspd arguments come from fixed templates; paths are our own work folders (GUID names) and are validated before use.
- **Cleanup and nothing in the image**: removed at the end and checked by `Test-AVDTuneBenchmarkClean`: work folder, share test folder, attached test VHDX (detached before delete), SMB connections, restore journal and the restore task, services back to their earlier state, HKCU policy values, Outlook test profile and PST, temporary Edge profiles, Office test files, diskspd cache (`C:\ProgramData\AVDTune\tools\diskspd`, removed at "Abschliessen"). "Abschliessen" (plan 7a) refuses while this check finds anything. The results (JSON, HTML) stay in `C:\ProgramData\AVDTune\benchmark\` as part of the change log state (plan 7); they hold no secrets.

## 7. Stand-alone script (repo `dominguez-posh/AVD-Benchmark`)

- Same engine: `Modules/AVDTune.Benchmark.psm1` and `AVDTune.Bench.exe` of the same AVDTune release, same benchmark version and reference, so the results are comparable with the master.
- Entry `Invoke-AVDBenchmark.ps1` (Windows PowerShell 5.1, elevated): `-Name <system name>`, `-Notes`, `-Share <UNC>`, `-ShareAuth CurrentUser|Key|User` (key or password asked with `Read-Host -AsSecureString`, never a parameter value), `-Mode Full|Quick`, `-Capacity`, `-OutDir`. No sign-in, no Azure; Azure facts (size, region, disk) come from the instance metadata service when the host runs in Azure, otherwise "unbekannt". Output HTML, PDF and JSON (kind `standalone`), for import into AVDTune as comparison system.
- Build and delivery (decision D11): the AVDTune release workflow builds `AVD-Benchmark-<version>.zip` (script, module, exe, data, `manifest.json` with SHA256 per file) from the same tag and publishes it as a release of `AVD-Benchmark`. The script checks its files against the manifest at start. diskspd is downloaded at run time as in section 6.
- The old script is replaced; its bugs (plan 6: fake download value, SMB 5x too high, 1024 instead of 4096 files, read-only diskspd without latency, PowerShell-only CPU, broken HTML, hard-coded share, bundled Ookla) do not exist in the new engine because each measure is defined above and covered by `Check-Benchmark.ps1`.

## 11. Status of round 2 (issue #14)

Built: application starts and Speedometer (`apps`), FSLogix score (diskspd on the share, `share`, VirtDisk profile container), GPU score, optional capacity simulation (`capacity`), HTML report per image version with the comparison to the previous version. Not live-verified on a VM: all of it runs against fakes and unit tests only.

Deviations from sections 1 to 4, each for a reason that does not need a decision of the user now:
- No UI Automation (the self-contained runtime has no managed wrapper without a third-party library): "ready" is the window class visible (Word `OpusApp` with `_WwG`, Excel `XLMAIN` with `EXCEL7`, Explorer the new folder window by title, Edge the page call-back) plus `WaitForInputIdle`. The capacity probe is a fixed set of work steps with the cost pattern of each application (CPU burst, memory, small files, a PowerShell start), timed per action; it touches no window and sends no input.
- Outlook (test profile and PST) and Teams (AUMID, window class not verified) are `skipped` with the reason. No HKCU policy values to suppress first-run dialogs (a change of the master, value names not verified).
- GPU: 3D scene, DirectCompute; hardware encode and decode (async MFT) are `unsupported` ("not part of this version"), so the GPU score is a partial score and says so.
- The Speedometer copy (62 MB, 1118 files) is not in the repository yet: without `Bench\data\speedometer-3.1\index.html` the measure is `skipped`.
- Reference values of all new measures are placeholders with `calibrated: false`; results and the report say "nicht kalibriert".
- Environment of the child: only the application starts and the capacity run get USERPROFILE, APPDATA, LOCALAPPDATA, USERNAME, USERDOMAIN, COMPUTERNAME, HOMEDRIVE, HOMEPATH (Office and Edge need a profile); the values come from the Windows folder API and the token, never from the inherited environment.
- Programs of the application starts: path from HKLM App Paths or the Windows folders, admin-only folder, Authenticode of Microsoft (`Test-AVDTuneToolTrust`), file held open with `FileShare.Read` for the whole run; the measure program accepts only such a path below Windows or Program Files with the expected file name.
- Rights of the application starts (issues #14 N1, #84): the programs run with a token made from AVDTune's own token by `CreateRestrictedToken` (LUA_TOKEN, only SeChangeNotifyPrivilege), Medium integrity, owner and default DACL the user and SYSTEM. Deny-only are Administrators, the other built-in admin-like groups (Power Users, Account, Server, Print and Backup Operators, Replicator, S-1-5-32-554, Network Configuration Operators, S-1-5-32-569, Hyper-V Administrators), S-1-5-114, and every domain group of the token with RID 498, 512, 516, 517, 518, 519, 520, 521, 526, 527 or 553 (found in TokenGroups, the SIDs differ per domain). The token is read back before use and the started program after it (not elevated, Medium or lower, none of these groups usable, standard-user privileges only); otherwise nothing starts (fail closed). `AVDTune.Bench.exe selftest-launcher` (elevated) shows each point.
- App starts only with a local admin (#84, point 2): when AVDTune runs as a member of a domain-privileged group (Domain Admins, Enterprise Admins, Schema Admins and the other RIDs above, not deny-only), the measure program refuses every application start and reports the measure as failed with "app starts only with a local admin". Reason: the reduced token shares the admin's logon session, so Kerberos and NTLM single sign-on still act with the admin's network identity, whatever the local groups are (the same holds for UAC and Safer tokens). Run the benchmark on the master with the local admin account.
- Residual risk (#84, point 3): the user SID stays usable in the started programs, so the admin's own HKCU and profile (Run keys, Startup folder, PowerShell profile, Office add-ins) are writable for them. For the built-in Administrator (RID 500, not filtered by UAC) something placed there runs with full rights at the next sign-in. Accepted for now because the programs are Microsoft-signed, start with throw-away profiles where they allow it (Edge InPrivate, own user-data folder) and run only in the job for the measure; the long-term fix is a throw-away standard user for the application starts (`LogonUser`), not built yet.
