# Language and region page (phase 6, issue 56 part 1)

Language packs and Language Features on a Windows 11 multi-session master, and the defaults new users get at their first sign-in. Code: `Modules\AVDTune.Language.psm1`, page `AVDTune-Language.ps1` (built in code, next to the other pages), checks `Tests\Check-Language.ps1` with `Tests\Fakes\FakeLanguage.ps1`, smoke step `language page`.

## What it does
- **Installed languages and features**: read from `Get-InstalledLanguage` (LanguagePackManagement), with `Get-WindowsCapability -Online -Name Language.*` as the fallback. Read only.
- **Add languages**: multiple selection of the 18 common languages (same list as the Office page: de-DE, en-US, en-GB, fr-FR, it-IT, es-ES, nl-NL, pl-PL, pt-PT, pt-BR, sv-SE, da-DK, nb-NO, fi-FI, cs-CZ, tr-TR, ja-JP, zh-CN). Installed ones are ticked and fixed. A language is installed with the steps of the Learn script: the client language pack (`Add-Package`), the five language features as capabilities (Basic, Handwriting, OCR, Speech, TextToSpeech) and, for ja-JP (`Jpan`) and zh-CN (`Hans`), the font capability. Handwriting, OCR, Speech and TextToSpeech are optional (a missing .cab on the ISO is noted and skipped); the pack and Basic are required.
- **Content folder, no download by AVDTune**: the Learn guide installs from the `LanguagesAndOptionalFeatures` content of the Microsoft ISO. The administrator names the folder. DISM runs with `/Source` and `/LimitAccess`, so it never goes to Windows Update or the internet. The path must be a plain local drive path or `\server\share\...` (regex anchored at both ends, plain components only). Refused: relative paths, `..`, a `.` part, `/`, device and long paths (`\.\`, `\?\`), `:` (streams), administrative shares (`X$`), `localhost`, loopback addresses, the name of this computer. Then (`Get-AVDTuneLanguageSourceVerdict`, probe-based so the checks run with a fake): the folder must exist, and **every part of the path up to the drive root or the share root** must not be a link. Only an ISO that Windows mounted itself counts as read-only media (a CD drive that belongs to a virtual disk image, `Get-Volume | Get-DiskImage`): the ISO must be mounted by the administrator, AVDTune does not check where the ISO file came from (use the Microsoft ISO) and does not read the permissions of the media. A physical optical drive is checked like a local folder. A mapped network drive counts as a share (permissions read in every part, root included); a drive made with `subst` is refused. The folder is checked again directly before every language is installed, not only on the page. Every other folder, local or share, must be admin-only in **every part including the root** (permissions are read for each; a drive root like `C:\` lets users create folders and is refused; a share is no longer accepted without reading). Share permissions themselves cannot be read from the client: the confirmation for a share says so (text depends on the kind: share, local folder, read-only media).
- **Cleanup off**: before the first language the three scheduled tasks (`Pre-staged app cleanup`, `LPRemove`, `Uninstallation`) are disabled and `BlockCleanupOfUnusedPreinstalledLangPacks = 1` is set (Learn script, first lines), each as a step with Test/Apply/Undo. Otherwise Windows removes the packs again.
- **Defaults for new users** (block "Defaults for new users", one dropdown each): display language (UI) and sign-in screen (only installed languages; a missing one is listed with "not installed, offered for installation first" and Apply then asks to install it first), regional format, input (default keyboard of the language), location (GeoId), system locale (programs without Unicode, restart needed), time zone (the Azure region from IMDS `location` only **suggests** a zone: the list marks it and the line next to the dropdown names it; the dropdown stays on "(keep as it is)" unless you choose or saved a zone; the table is in the module). The values are set for the account that runs AVDTune (`Set-WinUILanguageOverride`, `Set-Culture`, `Set-WinUserLanguageList` with the input tip, `Set-WinHomeLocation`) and copied with `Copy-UserInternationalSettingsToSystem -WelcomeScreen $true -NewUser $true` (Windows 11). `Set-WinSystemLocale` and `Set-TimeZone` set the rest. A dropdown left on "(keep as it is)" keeps the value found now, so the copy never changes a value that was not chosen.
- **Actual state for new users** is read from `HKEY_USERS\.DEFAULT` (welcome screen and system accounts, the target of the copy): `Control Panel\Desktop PreferredUILanguages`, `Control Panel\International LocaleName`, `Control Panel\International\Geo Nation`, `Keyboard Layout\Preload 1`; system locale from `HKLM\SYSTEM\CurrentControlSet\Control\Nls\Locale (default)` (LCID), time zone from `TimeZoneInformation TimeZoneKeyName`. The default profile (`C:\Users\Default`) itself is not read (that would need a hive load); the test VM must show that it matches (#17).
- **Test / Apply / Undo**: every setting is a step (`language.*`) behind the write gate (`Invoke-AVDTune`: Test before and after, run record, `LastChange`, change log, category Language, central change marker). Test (dry run) works without the gate and changes nothing. Before the first change the values found are kept in `config\language-undo.json` (new users, the administrator, system locale, time zone) and never overwritten; `config\language-applied.json` names the steps this tool really changed. Undo puts back only those (typed read of the record; a damaged record changes nothing), then the administrator's own settings last, then checks every restored value against the earlier one (a value that is not back, or was never recorded, is reported as "Not restorable" and the record is kept). A later run completes values the record does not hold yet and AVDTune has not changed since; recorded values are never overwritten. **Undo defaults does not switch the language pack cleanup protection back on** (the three tasks stay off and the policy value stays 1, so installed packs are not removed); the module can undo it with `-IncludeCleanup`, then the policy goes back to the value found before (kept in the record), not just deleted.
- **Confirmation of Apply** lists every change per setting (old -> new); a setting that stays is not listed.
- **Cannot be undone**: installing a language pack. AVDTune has no step that removes one. The confirmation says so in plain words (only a snapshot of the VM brings the earlier state back) and names that after a language pack the latest cumulative update may have to be installed again (Learn).
- **Background**: install and apply run in a background runspace with a task on the task bar (`language-languages`, `language-defaults`, `language-all`, `language-undo`); closing the window and signing out are held back while it runs. The real adapter is created in the runspace; in test mode everything runs inline with the fakes.

## Programs and trust
- DISM only through `New-AVDTuneUpdateAdapter` (`Path 'Dism'` = `System32\Dism.exe` from `Get-AVDTuneSystemFolder`, never PATH): Authenticode with the tool table (`Test-AVDTuneToolTrust`, Microsoft, original file name `Dism.exe`), then `Run` = `New-AVDTuneChildStartInfo` (central child environment, no shell, no window) inside a job object with a timeout that ends the tree.
- The PowerShell cmdlets of the international settings run in the process of AVDTune (like the Defender cmdlets of the Optimization page), never as a program started from text. Every writing member of the real adapter checks its arguments against fixed lists again (languages, cultures, input tips, GeoIds, time zones known to Windows).
- Tag, source and every other value are validated before they reach a command line (`Get-AVDTuneLanguageDismCalls` builds the argument list as data).

## Checks of the worker
The background worker is tested like #67: `Tests\Check-Language.ps1` reads the import lines and the worker text from `AVDTune-Language.ps1` (no copy), starts a fresh runspace with exactly those imports, runs the closures of the real adapter with the fake update adapter and the worker text with a fake machine, and fails if anything is "not recognized". A counter-test removes the Language import and expects the probe to go red.

## Not verified (needs the test VM, listed as check points in #17)
- The real probe of the content folder: `IsSubst` (QueryDosDevice target `??`), `IsMountedIso` (`Get-Volume | Get-DiskImage` for a Windows-mounted ISO) and the permission read of a drive root or a share root.
- The whole real flow: DISM calls with `/Source` from a mounted Languages and Optional Features ISO (exit codes 0 and 3010 assumed success), time per language, whether the Learn feature list for the ISO of 25H2 has the same names (`Language.Basic~~~de-DE~<version>` ...), the optional ones for each of the 18 languages, and the font capability name for ja-JP/zh-CN (`Language.Fonts.Jpan~~~und-Jpan~<version>`, `...Hans...`).
- The Learn script uses the mapping table CSV (Windows 10 1809 FOD to LP) to find a different source language for some languages; AVDTune does not read it and uses the language itself. Languages that need a different source (or satellite packs) are not covered.
- The Local Experience Pack (`LocalExperiencePack\<tag>\LanguageExperiencePack.<tag>.Neutral.appx`, `Add-AppProvisionedPackage`) and the update of the inbox apps with the Inbox Apps ISO are not done; the Learn article for Windows 11 only mentions a Remove-AppxPackage cleanup for an Internet-connected VM. The cleanup of leftover language experience packs before sysprep is not done (the master is never sysprepped by AVDTune).
- That after a language pack the latest cumulative update must be installed again (Learn, Windows 10 article): AVDTune only says it; it does not reinstall.
- `Get-InstalledLanguage` on Windows 11 multi-session (and the property names `LanguageId`, `LanguagePacks`, `LanguageFeatures`), and the capability fallback.
- Reading the state from `HKEY_USERS\.DEFAULT`: that `Copy-UserInternationalSettingsToSystem` writes exactly these values there (UI language in `Control Panel\Desktop PreferredUILanguages` or `MUILanguagePending`, geo in `Control Panel\International\Geo Nation`, keyboard in `Keyboard Layout\Preload`), and that the default profile for new users gets the same (new local profile on the test VM, first sign-in, check language, format, keyboard, location).
- That the new display language reaches a user with an FSLogix profile created later (profile creation time), and that users who already have a profile keep theirs.
- `Set-WinUserLanguageList -LanguageList` with one language replaces the whole list of the administrator (the administrator's own list is restored by Undo only for UI, format, input tip and location, not for further languages in the list).
- `Set-WinSystemLocale` (restart needed) and the read of the system locale from `Nls\Locale (default)` as an LCID; the Windows time zone ids of the Azure region table (a suggestion only; a missing region has none).
- That the unchanged "keep as it is" choice keeps new-user settings consistent when the administrator's own values differ from `.DEFAULT` (the copy always starts from the values AVDTune sets on the administrator first).
- Behaviour of `Copy-UserInternationalSettingsToSystem` in a background runspace without a desktop (elevated, not interactive).
